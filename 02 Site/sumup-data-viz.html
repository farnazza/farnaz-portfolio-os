A reusable bar chart system for SumUp

In 2022, I co-created a reusable bar chart design system for data visualization at SumUp. I documented its anatomy, state model and size variants, which was implemented in 2024 as part of the SuperApp vision, in the sales and payout widgets, and made sales performance easier to understand across mobile and web.

01. The problem

Teams needed to visualize sales and other time-series metrics, but there was no shared bar chart component with clear rules for anatomy, interaction and sizing.

Charts built case by case

Different teams were designing charts independently, and designers were rebuilding them for each case.

Inconsistent behavior

This led to inconsistent layouts, interactions and accessibility behavior across products.

Dashboard and mobile

It was hard to guarantee consistent behavior, accessibility or performance across dashboard and mobile.

One system that scales

We needed a documented system that made it easy to drop in a chart widget that “just works” in different sizes and states.

02. What I did

I co-designed the data viz patterns and led the documentation of a simple vertical bar system.

  1. 01 · Atomic element and anatomy

    What: Started with the smallest atomic element: a single vertical bar.

    How: Defined its width, radius, color tokens, and focus and selection treatments, then mapped the widget anatomy: axes, labels, grid, selection affordances and legends.

    Outcome: Each part of the widget had a clear role and spec.

  2. 02 · Interaction and states

    What: Defined the interaction states: default, hover, active or selected, dimmed or inactive, and empty.

    How: Made each state change visually clear, with enough contrast, clear focus outlines and no reliance on color alone.

    Outcome: State changes that are clear and accessible.

  3. 03 · Time ranges and size variants

    What: Documented how the widget adapts across time ranges and container sizes.

    How: Rules for bar count, spacing, truncation, and how labels scale down for compact variants.

    Outcome: One widget for different dashboard and homescreen contexts.

  4. 04 · Specifications and behavior

    What: Created detailed specifications and behavior guidelines.

    How: Spacing, typography and color usage, plus how tooltips, value reveals and horizontal scrolling work when there are more data points than fit.

    Outcome: Designers and engineers could assemble charts from the same building blocks for dashboard, web and mobile.

03. Key decisions

Data visualization in SumUp should be easy and simple, so that merchants can make business decisions based on understanding the data.

Black and white

Our charts are black and white, the most powerful combination in terms of contrast. It makes graphics understandable for the majority of people.

Shapes, not colors

Different patterns and shapes represent different values, so the charts don’t rely on color.

A widget system

To give flexibility to create dynamic dashboards and effective data viz, the library is based on a widget system.

04. Outcome

The output was a documented bar chart widget system: a single set of atomic elements and rules that can generate multiple chart widgets across dashboard and mobile.

Drop in and go

Designers can choose the size and time range, drop in the bar chart widget, and know that interaction, motion and accessibility work the same everywhere.

Live in the SuperApp

In 2024, the system was implemented as part of the SuperApp vision, in the sales and payout widgets.

Shared building blocks

Designers and engineers assemble charts from the same building blocks for dashboard, web and mobile.
